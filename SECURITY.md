# Security policy

## Supported versions

Security fixes are applied to the latest revision of `main`. Older commits, branches, forks, and
previous releases may not receive fixes.

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability.

Use GitHub's **Report a vulnerability** flow in the repository's Security tab when private
vulnerability reporting is available. Otherwise, contact the maintainer privately using a contact
method listed on the [repository owner's GitHub profile](https://github.com/vinayaksonthalia).

Include a concise description, affected revision, reproduction steps or proof of concept, expected
impact, and any suggested mitigation. Do not include real financial records, credentials, API keys,
certificate signing keys, or personal data.

The maintainer will acknowledge a complete report as soon as practical, investigate it, and coordinate
disclosure and remediation with the reporter. Response times are targets, not guarantees for this
volunteer-maintained project.

## Security boundaries

Untangle is decision-support and reconciliation software. It must not be treated as authorization to
move money, post entries without review, or expose raw financial inputs to external agents. Synthetic
test data and test-mode integrations should be used for demonstrations and vulnerability reports.
